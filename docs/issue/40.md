# Issue #40 — 占領後の移動

- Issue: https://github.com/snowleaf-com/sengoku-nihonshi.net/issues/40
- 実装: [`../impl.md`](../impl.md) の W

## 修正前の状態

`src/services/commands.ts` の戦争勝利分岐は、領有・残兵・貢献を更新するが、攻撃者の所在を更新していない。`CharacterRepository.updateResources` も所在を更新する API ではない。

`test/phase-n4.test.ts` の占領テストは領有や残兵を検証するが、攻撃者の所在は検証していない。コード上で報告と一致する更新漏れを確認した。回帰テストを追加し、修正前に中立地・敵武将・滅亡を伴う占領の3ケースで所在の更新漏れを再現した。

## 方針

最優先の不具合修正として独立して対応する。占領に成功した攻撃者だけを占領先へ移動させ、そのまま守備につける。敗北・ラウンド上限での撃退は元の所在を維持する。

所在更新には既存の移動処理・リポジトリ API を確認して使い、占領・残兵・所在・キュー消化が整合する順序にする。通常移動コマンドの追加消費や貢献は加算しない。攻撃者の所在・残兵・守備状態は同じ UPDATE で保存する。占領先の旧守備を解除した後で、攻撃者を守備状態にする。守備コマンド分の追加貢献は加算しない。

防衛側や滅亡した家の武将は強制移動させない。滅亡時は所在を維持して浪人化する既存方針を維持する。

## 検証方針

中立地の占領・敵国の占領（最後の領土を含む）で攻撃者の所在が変わって守備につくこと、侵攻失敗では変わらないことを検証する。キュー消化、残兵、守備解除、滅亡処理も既存検証と合わせて確認する。

占領後に次の予約コマンドが新しい所在を基準に評価され、Hub 再取得でも占領先を表示することを確認して完了とする。

## 実装・検証

占領成功時に所在と守備状態を残兵と同じ UPDATE で保存するよう修正した。中立地・敵武将・滅亡を伴う占領で移動と守備を検証し、侵攻失敗時は所在と非守備状態を維持することも検証した。全94テスト、typecheck、lint が成功。
